# PRD: Discord Translator

## 1. 概要

Discord Translator は、Discord Web で会話を読む・書くための Chrome 拡張機能である。
受信メッセージを日本語へ、投稿前の下書きを英語へ翻訳する。
翻訳先はローカルと ChatGPT から選択する。

外国語の会話では、単語の意味だけでは語調や冗談を理解しにくい。
外部ツールへのコピーと貼り付けは、会話の流れも妨げる。
本製品は原文に対応する訳文をその場に表示する。
スラングや言葉遊びには、理解の手掛かりとなる短い補足を付ける。

## 2. 目的

- 利用者が選んだ本文だけを翻訳し、会話を追いやすくする。
- 原文を残し、訳文と補足を照合できるようにする。
- 英訳した下書きを、利用者が確認・編集してから投稿できるようにする。
- ローカル処理と ChatGPT への送信を、利用者が選択できるようにする。
- サーバの起動と停止を、Chrome 拡張の利用に連動させる。

## 3. 対象ユーザ

macOS の Google Chrome で Discord を利用する個人を対象とする。
主な利用場面は、チャンネル、DM、スレッドでの短文の読み書きである。
ローカル翻訳には Apple Silicon Mac とモデルの準備が必要になる。
ChatGPT だけを使う場合、Python とローカルモデルは不要である。

## 4. スコープ

### 対象

- `https://discord.com/` の表示メッセージと新規投稿入力欄。
- メッセージごとの手動翻訳、順次表示、失敗時の再試行。
- 受信訳の短い補足と、解釈の不確実性の表示。
- 投稿前の英訳、入力欄への反映、「元に戻す」。
- 受信完成訳の端末内保存と、同じメッセージへの復元。
- 翻訳先の選択、ChatGPT 接続、Native Messaging による起動・停止。
- ローカル依存とモデルの固定・検証。

### 対象外

- Discord デスクトップアプリ、bot、サーバへの導入。
- 全メッセージの自動翻訳、自動投稿、周辺会話の自動収集。
- 投稿済みメッセージの編集、非テキストの下書きの翻訳。
- 相手の本心の判定、感情や本気度の数値化。
- 複数ユーザ向けの共有サーバ、LAN 公開、汎用推論サービス。
- `launchd` による常駐、起動時の依存・モデルの自動取得。

## 5. ユーザ要求

| 利用場面 | 利用者が得る結果 |
| --- | --- |
| 読みたいメッセージの「翻訳」を押す | 原文の直下で日本語訳を読み、必要な補足を確認する。 |
| 翻訳が失敗する | 原文を失わず、固定エラーコードを確認して再試行する。 |
| 同じメッセージを再表示する | 有効な保存訳を、再翻訳せずに読む。 |
| 日本語の下書きで「英語に翻訳」を押す | 英語の下書きを確認し、編集してから自分で投稿する。 |
| 翻訳前の下書きへ戻りたい | 「元に戻す」で直前の下書きを復元する。 |
| 外部送信を避けたい | ローカル翻訳を選び、同じ Mac 内で本文を処理する。 |
| ChatGPT を使いたい | 接続と送信先を確認し、利用枠を使って翻訳する。 |

## 6. 主要機能

<a id="11-訳文の順次表示2026-10-02"></a>

### 受信メッセージの翻訳

有効化中は、対象メッセージごとに「翻訳」を表示する。
訳文は生成中から原文の直下へ順次表示する。
完成結果を検証し、正常に終わった結果だけを確定する。

受信訳は、口語、スラング、絵文字、語調を考慮する。
説明が必要な表現には、最大2項目の短い補足を付けるよう指示する。
出力に `[補足]` がある場合だけ、固定の注意書きを表示する。
周辺会話は送信せず、曖昧な解釈は可能性として示す。

<a id="12-投稿前の日本語から英語への翻訳案2026-10-05"></a>

### 投稿前の英語翻訳

「英語に翻訳」は、対象入力欄の下書きだけを処理する。
完成した英訳を入力欄へ反映し、利用者が編集を続けられるようにする。
翻訳中に編集された下書きへ、古い結果を適用しない。
「元に戻す」は、直近の翻訳前の下書きを復元する。
拡張機能は投稿操作を行わない。

<a id="13-受信メッセージの翻訳文を5日間保持する案2026-10-05"></a>

### 受信訳の保存

補足を含む受信完成訳を、端末内に5日間保存する。
メッセージ、本文の識別値、翻訳先が一致する場合だけ復元する。
下書きと投稿用の英訳は永続保存しない。
補足に引用した原文の一部は、完成結果に含めて保存する。

### 翻訳先と起動

初期設定はローカル・無効である。
有効化時は、選択先の起動と接続を確認する。
翻訳先の切替では無効に戻し、選択先のサーバへ切り替える。
無効化は表示を取り除く操作であり、選択先のサーバは維持する。
Chrome の完全終了と拡張の無効化で、起動したサーバを停止する。

## 7. 非機能的な期待

- 手動操作なしに新しい翻訳を依頼しない。
- 受信翻訳と下書き翻訳を、共通の直列キューで処理する。
- 待機、通信、保存に有限の期限を設ける。
- サーバは loopback だけで待ち受ける。
- 本文、訳文、認証情報を通常の診断ログへ出さない。
- Discord 内の操作は Discord のテーマに追従する。
- ポップアップは OS の明暗設定に対応する。
- ボタンの標準キーボード操作と状態通知を提供する。

## 8. 制約

| 項目 | 制約 |
| --- | --- |
| 共通環境 | macOS、Google Chrome、Node.js 24 以上の LTS を基準とする。 |
| ローカル環境 | macOS 26 以降、Apple Silicon、native arm64 の CPython 3.14。 |
| ローカルモデル | `mlx-community/Qwen3.5-9B-MLX-4bit` を固定して使う。 |
| ChatGPT | Sign in with ChatGPT と利用枠の許可、インターネット接続が必要。 |
| 入力 | 1要求あたり最大8,000 UTF-16 コード単位。 |
| 保持 | 受信保存訳の有効期間は5日。復元では延長しない。 |
| 同時利用 | 手動サーバとの併用と複数 Chrome プロファイルの同時使用は対象外。 |

翻訳の意味、補足の頻度、書式の保持は、モデルの出力に依存する。
補足は相手の真意を保証しない。
ローカルモデルには直訳、誤説明、命令風本文への追従の制約がある。
Discord の DOM 変更により、検出や入力欄への反映が動作しなくなる可能性がある。

## 9. 成功指標

- 手動で選んだ本文に対応する結果を、その場で確認できる。
- 原文と入力欄の編集を失わず、失敗から手動で復旧できる。
- 保存訳の復元で、翻訳 API を呼ばない。
- 翻訳先ごとの送信先と保存範囲を把握できる。
- 起動や翻訳の失敗を、成功した状態として表示しない。

機械的な合否は [受け入れ条件](REQUIREMENTS.md#9-受け入れ条件) を参照する。
意味の品質評価と実機確認は、自動テストと分けて扱う。
検証の記録は `docs/plans/` に保存する。
