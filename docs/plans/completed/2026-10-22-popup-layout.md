## Goal

利用者は、ポップアップの情報と操作の関係を把握できる。
利用者は、翻訳先の選択から有効化までの操作を理解できる。
既存の機能を維持し、名称と見た目を整える。

## Scope

- `extension/popup.html` の見出し、情報の配置、操作説明。
- `extension/popup.css` の余白、配色、枠線、操作状態の装飾。
- `extension/popup.js` は、採用する表示文言の整合が必要な箇所だけ。
- 既存の popup、provider、Native 起動テストによる回帰確認。
- `docs/current/REQUIREMENTS.md` の画面要件と受け入れ条件。
- `docs/current/SPECIFICATIONS.md` の表示内容と操作説明。
- `docs/current/DESIGN.md` の popup HTML/CSS の責務説明。
- README は、既存の操作名を変更する場合だけ同期する。

## Non-goals

- 翻訳、接続確認、認証、Native 起動の処理変更。
- 選択肢、ボタン、設定項目、権限、外部依存の追加。
- 拡張名、ChatGPT の名称、認証ボタン名の変更。
- Discord 内の翻訳 UI とテーマ機能の変更。
- 新しいアイコン、画像、外部フォント、アニメーション。
- 新しい ADR と PRD の作成。

### 承認された画面仕様

「表示内容の維持」は、既存の情報と操作を残す意味と解釈する。
ユーザは、以下の見出しと短い操作説明の追加を承認した。

| 上からの順序 | 表示と配置 |
| --- | --- |
| 拡張名 | `Discord Translator` を可視の見出しにする。 |
| 翻訳先 | 既存のラベルと select を、一つの領域にまとめる。 |
| ChatGPT 接続 | 既存の説明、状態、接続操作、利用量リンクをまとめる。 |
| 有効化 | 既存の checkbox、操作説明、状態、エラーコードをまとめる。 |

- ChatGPT 接続領域は、既存どおり選択に応じて表示する。
- 外部送信と利用枠の説明は、接続ボタンより前に表示する。
- 接続ボタンを先に置き、状態確認と切断を後に置く。
- 接続アカウント、モデル、遠隔失効未確認の案内を省略しない。
- 有効化のラベルは `Discord Translator を有効にする` とする。
- 操作説明は `有効にすると Discord に翻訳ボタンを表示します。` とする。
- `翻訳はボタンを押したときに実行します。` を説明に続ける。
- 既存の有効化案内は、採用したラベルと一致させる。
- 有効化が翻訳要求を自動送信するような説明は加えない。

CSS の仕様は、次の範囲とする。

- popup の幅は余白込み 360px とし、小さい初期 viewport の幅へ縮めない。
- 長い状態文、アカウント、モデル、コードは折り返す。
- 操作ボタンは重ならず、必要な高さを popup 内に確保する。
- 明色と暗色の表示を維持する。
- 文字、背景、操作境界には判読できる明暗差を設ける。
- 青紫色 `#5865F2` をアクセントカラーとする。
- アクセントの場所は、見出し下線、翻訳先 select の枠、有効化領域の左線とする。
- その他の装飾は中立色を使い、エラーの色は別に維持する。
- hover、focus、disabled を区別できる表示にする。
- 色だけで有効・無効、接続状態、失敗を伝えない。

### 維持する動作と境界

- MUST: 既存の要素 ID、label の関連付け、hidden 制御を維持する。
- MUST: status の通知とキーボード操作を維持する。
- MUST: 操作中の disabled と設定の復元を維持する。
- MUST: 接続確認に成功した場合だけ、有効化する。
- MUST: 翻訳先の変更と ChatGPT の切断では OFF にする。
- MUST: 認証後の再操作案内と、状態別のエラー表示を維持する。
- MUST: health の timeout、応答検証、認証 URL の検証を維持する。
- MUST: Native ready 待機、通信先、保存、権限を変更しない。
- MUST: 装飾変更による新しい通信や翻訳要求を発生させない。

### 2026-10-22 実 Chrome での幅崩れの修正

- ユーザの画像で、popup が極端に細くなる不具合を確認した。
- 先行の通常タブによる表示確認では、不具合を検出できなかった。
- `max-width: 100vw` が、小さい viewport に本文の幅を制限していた。
- Chrome の自動サイズ計算との相互作用が、幅崩れの原因と考えられる。
- 修正は `popup.css` の上記 1 行の削除だけである。
- 幅 360px、余白、配色、長い値の折り返しと既存の処理は維持した。
- 一時的な回帰確認用ページで、実 HTML/CSS/JS を表示した。
- iframe の初期幅を 72px とし、内容の幅に合わせて 3 回更新した。
- ローカルと ChatGPT の両方で、修正前は幅 72px のままだった。
- 両翻訳先とも、修正後は 360px に拡大して同じ幅を維持した。
- 修正後は、可視要素の横方向のはみ出しがなかった。
- 同じ JavaScript の全 112 テストは先行実装で成功している。
- 本修正は CSS だけのため、JavaScript のテストは再実行していない。
- 実 Chrome の自動サイズ計算自体を再現した試験ではない。
- 実 Chrome へ接続する操作手段がなく、エージェントによる拡張内の再確認は未実施である。
